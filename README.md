# YT Looper

YT Looper is a lightweight Firefox, Chrome and Safari extension for repeating an A/B fragment of a
YouTube video at a custom playback speed.

## Current scope

The current desktop build targets regular YouTube watch pages in Firefox, Chrome and Safari. It
includes:

- A/B points from the current playback position or numeric inputs.
- Fine adjustments in 0.1 second increments.
- Playback speeds from 0.25× to 4×.
- Pitch preservation is always enabled for useful music practice playback.
- Per-video A/B persistence and global playback preferences.
- Automatic suspension while a YouTube ad is playing.
- A dedicated spinner replaces video controls until an ad finishes.
- Support for YouTube's in-page navigation.
- Keyboard shortcuts: `Alt+Shift+A`, `Alt+Shift+B`, and `Alt+Shift+L`.
- A toolbar library with named folders and reusable fragments.
- One-click opening of a saved fragment with its loop and speed activated.
- Nested, collapsible folders and an animated modal fragment editor.
- Compact, icon-based controls and Spanish/English interface localization.
- Direct fragment saving from the on-video widget, with duplicate prevention.
- A saved-fragment badge with one-click A/B/speed synchronization.
- Drag-and-drop movement of fragments between library folders.
- Self-contained shared-loop links with validated A/B/speed payloads.
- A dismissible on-video widget that can be restored from the toolbar popup.

On macOS, `Alt` is the Option key: use `⌥⇧A`, `⌥⇧B`, and `⌥⇧L`.

## Fragment library

Open the YT Looper toolbar button from any page to browse a collapsible tree of saved fragments and
nested folders. When the active YouTube video has valid A/B points, a contextual section offers to
name and save that fragment. Select a fragment to rename it, move it, edit A/B or speed, open it, or
delete it. Opening a saved fragment creates a YouTube tab, seeks to A, restores its speed, and
activates the loop.

The on-video widget deliberately contains no naming or folder form. Its compact save icon stores a
new loop in the library root with an autogenerated name; names and folders are edited only from the
toolbar library. Once saved, its name appears above A/B in a green badge. Changing A, B or speed
turns that badge orange and changes the save icon into an update action. The badge's × action
detaches the saved fragment without deleting it, keeping the current parameters ready to become a
new fragment.

Keyboard events from the widget's numeric inputs are stopped before they reach YouTube, so typing
values cannot trigger the site's playback shortcuts.

The fragment editor opens as an animated modal sheet after explicitly selecting a saved fragment in
the tree. It overlays the popup instead of pushing the library down; closing it clears that
selection, so opening it again requires another click on the fragment.

The toolbar popup puts the folder tree first and the current-loop viewer second. Its current-loop
row uses one consistent language: blue means ready to save, green means synchronized and orange
means modified. Saving a new loop opens the same modal sheet so its generated name, A/B points,
speed and destination folder can be reviewed before creating it. The compact update action remains
available beside a modified saved loop.

When the active loop comes from a saved fragment, both the toolbar popup and the on-video contextual
controls show its saved name in a compact badge. Changes to A, B, or speed can be synchronized from
either place without changing the fragment name or folder. Drag a fragment row onto any folder
(including the library root) to move it; the editor's folder selector remains available as an
alternative.

Use the ↗ action in either interface to copy a canonical `youtube.com/watch?...#ytl=…` link. The
Base64URL payload contains only its version, video ID, A, B and speed—not the cosmetic name or
folder. Opening it with YT Looper installed validates the payload, seeks to A and activates the
loop; it remains unsaved until the user chooses a default or custom name. Without the extension, it
opens as a normal YouTube link near A.

A small startup script captures loop and bookmark parameters at `document_start`, before YouTube can
normalize them out of the visible address. The heavier controller still loads at `document_idle`.

The close button appears while the widget is expanded. Closing it hides the widget for that video
while keeping shortcuts and loop behavior available; use **Show panel** in the toolbar popup to
restore it. The interface follows Firefox's language and currently includes Spanish and English.

When a video has no A/B parameters yet, the widget starts collapsed and expands automatically when
the first point is marked.

No browsing data or video content is collected or transmitted.

## Local development

Prerequisites: a current Node.js installation and Firefox, Chrome or Safari.

```bash
npm install
npm run check:full
npm run firefox
```

`npm run firefox` builds the extension and launches a temporary Firefox profile through `web-ext`.
To load it manually, run `npm run build`, open `about:debugging#/runtime/this-firefox`, select
**Load Temporary Add-on**, and choose `dist/firefox/manifest.json`.

For Chrome, run `npm run build:chrome`, open `chrome://extensions`, enable **Developer mode**,
choose **Load unpacked**, and select the generated `dist/chrome` directory. Chrome uses its own
Manifest V3 file and raster icon set while sharing all product code, storage formats and tests with
Firefox.

For a temporary Safari installation, run `npm run build:safari`, open **Safari → Settings →
Developer → Add Temporary Extension…**, and select `dist/safari`. Safari uses its own Manifest V3
file with an explicit YouTube host permission. See [Safari development](docs/SAFARI.md) for
temporary installation, Xcode wrapper generation and distribution details.

Other commands:

```bash
npm run build:watch       # Rebuild content.js while editing
npm run build:chrome      # Build the Chrome MV3 extension
npm run build:safari      # Build the Safari MV3 extension
npm run build:all         # Build all three desktop browsers
npm run fixture           # Local YouTube-like page for UI checks
npm run test              # Unit tests
npm run test:coverage     # Full suite with enforced coverage thresholds
npm run typecheck         # Strict TypeScript check
npm run lint              # TypeScript, CSS, HTML and Markdown linters
npm run check             # Reproducible offline CI quality gate
npm run check:full        # Quality, security, signatures and dependency freshness
npm run package:firefox   # Create the AMO upload archive
npm run package:chrome    # Create the Chrome Web Store archive
npm run package:safari    # Create the temporary Safari archive
npm run release:package   # Build the complete versioned GitHub Release bundle
npm run safari:project -- --bundle-id=com.example.ytlooper
```

Generated files live under `dist/` and `artifacts/` and are not committed. Chrome and Safari
packages are written beneath their own artifact directories so they cannot overwrite the Firefox
archive.

manifests/      Browser-specific manifests
